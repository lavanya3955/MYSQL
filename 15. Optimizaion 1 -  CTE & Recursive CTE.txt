CTE (Common Table Expression)
-----------------------------------------------------------------------------------------------------------
What is CTE?

A CTE (Common Table Expression) is a temporary result set defined using the WITH clause.
It improves readability and can even be recursive for hierarchical data.
It is a temporary named result set (like a virtual table) that you can use within a 
single SQL statement.
A CTE is a query inside a query, created using the keyword WITH.

The query inside the parentheses runs first.The result (CTE) can then be used like a table in the main query. 

Think of a CTE as a sticky note where you write a small part of your work:
Instead of repeating the note everywhere, you refer to it by name.
Makes your “work” (SQL query) neat, organized, and easy to follow.


Create a temporary table → use it immediately in your query

WHY ? - CTE is used to make complex SQL easier, cleaner, and reusable.

Makes query easy to read
Avoids repeating subqueries
Breaks complex query into steps


-----------------------------------------------------------------------------------------------------------
Syntax

WITH cte_name AS (
SELECT ...
)
SELECT * FROM cte_name;

example:

WITH dept_avg AS (
    SELECT department, AVG(salary) AS avg_salary
    FROM Employees
    GROUP BY department
)
SELECT *
FROM dept_avg;

Example 2: CTE with Aggregate

Find employees earning above average salary

WITH AvgSalary AS (
SELECT AVG(salary) AS avg_sal FROM Employees
)
SELECT name, salary
FROM Employees
WHERE salary > (SELECT avg_sal FROM AvgSalary);
---------
same with subquery:

SELECT *
FROM Employees
WHERE salary > (
        SELECT AVG(salary)
        FROM Employees
);
------------

using jus having 

SELECT emp_id, name, salary
FROM Employees
HAVING salary > (SELECT AVG(salary) FROM Employees);

---------

Explanation of above :
WITH creates a CTE (temporary result set).
AvgSalary is the temporary table name.
It calculates average salary from the Employees table.

Reads all employees from Employees.
Fetches average salary from the CTE

What is Recursive CTE?
-----------------------------------------------------------------------------------------------------------
A Recursive CTE is a CTE that refers to itself to solve problems step-by-step.

It is used for hierarchical data (like employees, managers, tree structure).
-- Numbers Generation
-- Date Generation
-- Hierarchy Levels
-- Organization Chart (Reporting Path)

It works like a LOOP inside SQL. Repeat a query again and again until a condition is met.

A recursive CTE is a CTE that calls itself to generate results iteratively.
Useful for hierarchical or iterative data, like organization charts, tree structures, or sequences.

A recursive CTE has two parts:
Anchor member → the starting point of the recursion - WHERE TO START
Recursive member → references the CTE itself to fetch next levels-   WHAT TO REPEAT

syntax:

WITH RECURSIVE cte_name AS (

1. Anchor Query   → Starting point x=0
UNION ALL
2. Recursive Query → Repeats using previous result x=x+1

)

SELECT * FROM cte_name;

-----

Step 1 result → used to generate Step 2
Step 2 result → used to generate Step 3

Recursive CTE is used when values follow a pattern or rule.

Important Notes

Always use UNION ALL
Must have stopping condition (to avoid infinite loop)
Condition → stops recursion

-----------------------------------------------------------------------------------------------------------
RECURSIVE CTE USING NUMBERS:
-----------------------------------------------------------------------------------------------------------
Note:Recursive CTEs can solve programming-style problems like factorial, Fibonacci, even numbers, 
and odd numbers. However, these are mostly interview or learning exercises. In real business, 
recursive CTEs are more commonly used for hierarchies and calendars for sequences.

Example 1: Generate numbers from 1 to 5

WITH RECURSIVE Numbers AS (
SELECT 1 AS num

UNION ALL

SELECT num + 1
FROM Numbers
WHERE num < 5

)
SELECT * FROM Numbers;

Output:
1
2
3
4
5

This query uses a Recursive CTE, which creates numbers dynamically in memory.

Because the condition is checked before adding +1, not after.
Recursive condition checks existing row, not the newly generated row

Calculate factorial values from 1 to 5.

);

INSERT INTO CalendarDates
WITH RECURSIVE dates AS (
    SELECT '2026-01-01' AS dt
    
    UNION ALL

    FROM dates
    WHERE dt < '2026-01-10'
)

## STEP 5: Requirement

Automatically assign joining dates:

Employee 1 → 2026-01-01
Employee 2 → 2026-01-02
Employee 3 → 2026-01-03
Employee 4 → 2026-01-04
Employee 5 → 2026-01-05

Instead of manual updates, we generate dates using Recursive CTE & update it.

---

WITH RECURSIVE date_cte AS (

    -- Anchor Row
    SELECT emp_id,
           DATE('2026-01-01') AS joining_date
    FROM Employees
    WHERE emp_id = 1

    UNION ALL

    -- Recursive Part
    SELECT e.emp_id,
           d.joining_date + INTERVAL 1 DAY
    FROM Employees e
    JOIN date_cte d
        ON e.emp_id = d.emp_id + 1
)

UPDATE Employees e
JOIN date_cte d
    ON e.emp_id = d.emp_id
SET e.joining_date = d.joining_date;

Build Employee Organization Chart Showing Reporting Path.
-----------------------------------------------------------------------------------------------------------

Display complete reporting structure showing who reports to whom.

CREATE TABLE Employees (
    emp_id INT PRIMARY KEY,
    emp_name VARCHAR(50),
    manager_id INT
);

INSERT INTO Employees VALUES
(1, 'CEO', NULL),
(2, 'Manager', 1),
(3, 'Developer', 2),
(4, 'Tester', 2),
(5, 'Intern', 3);

| emp_id | emp_name  | manager_id |
| ------ | --------- | ---------- |
| 1      | CEO       | NULL       |
| 2      | Manager   | 1          |
| 3      | Developer | 2          |
| 4      | Tester    | 2          |
| 5      | Intern    | 3          |

CEO
 └── Manager
      ├── Developer
      │     └── Intern
      └── Tester

SQL:

WITH RECURSIVE org_chart AS (

-- Anchor Query
SELECT emp_id,
       emp_name,
       manager_id,
       emp_name AS reporting_path
FROM Employees
WHERE manager_id IS NULL

UNION ALL

-- Recursive Query
SELECT e.emp_id,
       e.emp_name,
       e.manager_id,
       CONCAT(o.reporting_path,' -> ',e.emp_name)
FROM Employees e
JOIN org_chart o
ON e.manager_id = o.emp_id

)
SELECT * FROM org_chart;


+--------+-----------+------------+---------------------------------------+
| emp_id | emp_name  | manager_id | reporting_path                        |
+--------+-----------+------------+---------------------------------------+
|      1 | CEO       |       NULL | CEO                                   |
|      2 | Manager   |          1 | CEO -> Manager                        |
|      3 | Developer |          2 | CEO -> Manager -> Developer           |
|      4 | Tester    |          2 | CEO -> Manager -> Tester              |
|      5 | Intern    |          3 | CEO -> Manager -> Developer -> Intern |
+--------+-----------+------------+---------------------------------------+

CEO -> Manager -> Developer -> Intern

Creates complete reporting chain.
