3. Core Concept – Prompt Engineering

AI output quality depends on INPUT PROMPT.

Good Prompt = Correct SQL
Bad Prompt = Wrong SQL

We need to give Structured Prompting.

TASK 1 — STRUCTURED PROMPT DESIGN

Requirement:
Write a structured prompt to generate SQL.

Example Database Schema

Tables:

Customers(customer_id, customer_name, city)

Orders(order_id, customer_id, order_date)

OrderDetails(order_id, product_id, quantity, price)

Products(product_id, product_name, category)

Business Requirement

Find total revenue generated by each category.

Structured Prompt Format

Role:
Senior SQL Expert

Context:
You are working with the following schema:
Customers, Orders, OrderDetails, Products tables.

Constraints:

Use JOINS
Avoid subqueries if possible
Write optimized SQL
Use aggregation functions

Task:
Generate SQL query to calculate total revenue per product category.

Expected AI SQL Output
SELECT p.category,
       SUM(od.quantity * od.price) AS total_revenue
FROM Orders o
JOIN OrderDetails od
ON o.order_id = od.order_id
JOIN Products p
ON od.product_id = p.product_id
GROUP BY p.category;


AI works best when we provide:
✔ Role
✔ Context
✔ Constraints
✔ Task

This is called Structured Prompt Engineering.

TASK 2 — TEXT-TO-SQL STRATEGY (THE BUSINESS BRIDGE)

Problem:
Business users give vague requirements.

Business people usually do NOT speak technical language.

They explain what they want,
NOT how database or SQL should work.

Manager says:
"Show me our best categories."

AI cannot understand "BEST".

Step 1 — Clarification Prompt (VERY IMPORTANT)

Before writing SQL, AI must clarify.

Example Clarification Prompt:

"To generate accurate results, please clarify what you mean by 'best categories'. Should it be based on:

Highest Revenue
Most Units Sold
Highest Profit
Most Unique Customers
Number of Orders

Please confirm the metric."


GenAI should NOT guess business meaning.

Data Analyst responsibility:
Convert vague business language → measurable metric.

Step 2 — Execution (After Clarification)

Manager Response:
Best = Highest Revenue

SQL Query
SELECT p.category,
       SUM(od.quantity * od.price) AS revenue
FROM OrderDetails od
JOIN Products p
ON od.product_id = p.product_id
GROUP BY p.category
ORDER BY revenue DESC;
Explain to Students

Text-to-SQL Flow:

Business Question
↓
Clarification
↓
Metric Definition
↓
SQL Generation

This is called Business Bridge Thinking.

TASK 3 — LOGIC BASED QUESTION
Problem: Ambiguous Joins

User Request:
"Show Customer Orders"

Database contains:

Customers(customer_id, name)

Orders(order_id, customer_id)

ActiveCustomers(customer_id, status)

Now AI gets confused:
Which table to join?

Customers OR ActiveCustomers?

Why Text-to-SQL Tools Fail

Ambiguity occurs when:

Multiple tables share same column
Multiple join paths exist
Business meaning unclear

AI may generate wrong joins.

Correct Clarification Prompt

"Do you want:

Orders from all customers
OR
Orders only from active customers?"
SQL — Case 1 (All Customers)
SELECT c.name, o.order_id
FROM Customers c
JOIN Orders o
ON c.customer_id = o.customer_id;
SQL — Case 2 (Only Active Customers)
SELECT ac.customer_id, o.order_id
FROM ActiveCustomers ac
JOIN Orders o
ON ac.customer_id = o.customer_id
WHERE ac.status = 'Active';
