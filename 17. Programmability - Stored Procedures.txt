==========================================================
STORED PROCEDURES IN MYSQL
==========================================================

1. WHAT IS A STORED PROCEDURE?
----------------------------------------------------------

A Stored Procedure is a group of SQL statements stored in the database 
that can be executed together whenever needed.

A pre-written SQL program - Stored inside the database - Executed whenever needed

Simple Definition:
A Stored Procedure is a saved set of SQL statements that can be executed repeatedly using a 
CALL command.

NOte:— Stored Procedures normally work on EXISTING tables.
----------------------------------------------------------

2. WHY STORED PROCEDURES?
----------------------------------------------------------

We use stored procedures when:

- We want to reuse SQL logic
- We want to reduce repetitive queries
- We want faster execution
- We want better security
- We want to reduce network traffic

----------------------------------------------------------

3. KEY FEATURES
----------------------------------------------------------

- Can contain multiple SQL statements
- Can take input parameters
- Can return output
- Stored in database permanently
- Can be executed multiple times

----------------------------------------------------------

4. SYNTAX
----------------------------------------------------------

DELIMITER //

CREATE PROCEDURE procedure_name (IN parameter datatype)
BEGIN
    -- SQL statements
END //

DELIMITER ;

----------------------------------------------------------

5. REAL LIFE usage - Where Stored Procedures are Used
----------------------------------------------------------

Used by developers & applications
→ Backend (Java, Python, .NET) calls procedures to perform DB operations
Used in web applications
→ Example: When user clicks “Submit”, app calls a procedure
Used in automation jobs
→ Runs daily/nightly for reports, salary processing, data cleanup
Used for business logic
→ Complex operations (like banking transactions) handled inside DB
Used for security
→ Users don’t access tables directly, only execute procedures

2. OUT PARAMETER (OUTPUT)
----------------------------------------------------------

Purpose:

Create a stored procedure named total_employees that returns the total number of employees 
present in the Employees table using an OUT parameter.

Requirements
Use an OUT parameter to return the result.
Count total records from the Employees table.
Store the result into the OUT parameter.
Call the procedure and display the returned value.

Get total number of employees
----------

DELIMITER //

CREATE PROCEDURE total_employees(OUT total INT)
BEGIN
    SELECT COUNT(*) INTO total
    FROM Employees;
END //

DELIMITER ;

Usage:
CALL total_employees(@total);
SELECT @total;

CALL total_employees(@overall);

OUT parameter needs a user-defined variable (like @total) to store the returned value.
total → inside procedure - Exists only inside procedure - Used for internal calculation
@total → outside procedure - Exists outside procedure - Used to receive output

total ≠ @total


-- - SELECT COUNT(*) INTO total;
total =5
5=@total

Inside procedure → variables are local
Outside procedure → MySQL needs a variable to store output

That variable must start with @

REAL-TIME EXAMPLE: BANK MONEY TRANSFER USING STORED PROCEDURE

==================================================

1. SCENARIO
==================================================
A user transfers money from one account to another.

Instead of writing multiple SQL queries every time,
we use a stored procedure.

==================================================
2. CREATE TABLE
===============

CREATE TABLE Accounts (
acc_id INT PRIMARY KEY,
name VARCHAR(50),
balance INT
);

==================================================
3. INSERT SAMPLE DATA
=====================

INSERT INTO Accounts VALUES
(1, 'Ravi', 10000),
(2, 'Anu', 8000);

==================================================
4. CREATE STORED PROCEDURE
==========================

DELIMITER //

CREATE PROCEDURE transfer_money(
IN from_acc INT,
IN to_acc INT,
IN amount INT
)

BEGIN
UPDATE Accounts
SET balance = balance - amount
WHERE acc_id = from_acc;

UPDATE Accounts
SET balance = balance + amount
WHERE acc_id = to_acc;

END //

DELIMITER ;

==================================================
5. CALL PROCEDURE
=================

CALL transfer_money(1, 2, 2000);

==================================================
6. CHECK RESULT
===============

SELECT * FROM Accounts;

OUTPUT:
acc_id | name | balance
-----------------------

1      | Ravi | 8000
2      | Anu  | 10000

==================================================
7. WHAT HAPPENS INTERNALLY
==========================

* Amount is deducted from sender account
* Amount is added to receiver account
* Both operations happen using one procedure call

==================================================
8. REAL APPLICATION FLOW
========================

User → Click "Transfer Money"
→ Application sends request
→ Backend calls procedure
→ Database updates balances

ERROR HANDLING IN SQL-
==================================================

MySQL provides HANDLERS to control what happens when an error occurs inside:

Stored Procedures
Functions
Triggers

There are 2 handler types defined in SQL standard.

CONTINUE HANDLER-    continue executing further lines after the error

EXIT HANDLER - exit the procedure immediately when error happens


SYNTAX FOR HANDLER-

DECLARE handler_type HANDLER FOR condition action;

some examples of condition-

SQLSTATE'23000'(DUPLICATE KEY)
SQLSTATE'42000'(SYNTAX ERROR)
SQLEXCEPTION(ALL SQL ERRORS)
NOTFOUND(no result in cursor)
MYSQL_ERRNO 1062(duplicate key)

Ex:DECLARE CONTINUE HANDLER FOR SQLEXCEPTION
---------------------------------------------------------------------

Simple CONTINUE Handler Example
---------------------------------------------------------------------
Used when you want to continue execution even after an error.


Write a Stored Procedure named DemoContinue that performs the following:

Declare a CONTINUE HANDLER for SQLEXCEPTION.
When an error occurs, display the message:
Error occurred — but continuing execution
Inside the procedure:
Try inserting a record with an existing emp_id to intentionally generate an error.
Insert two more valid employee records.
Display a final message:
Procedure still running...


CREATE TABLE employees (
    emp_id INT PRIMARY KEY,
    name VARCHAR(50)
);

INSERT INTO employees VALUES (1,'sruthi');


DELIMITER $$

CREATE PROCEDURE DemoContinue()
BEGIN
    DECLARE CONTINUE HANDLER FOR SQLEXCEPTION
    SELECT 'Error occurred — but continuing execution' AS msg;

    INSERT INTO employees(emp_id, name)
    VALUES (1, 'John');   -- duplicate ID → triggers error
    INSERT INTO employees VALUES (2,'Geetha');
    INSERT INTO employees VALUES (3,'Ravi');


    SELECT 'Procedure still running...' AS status;
END $$

DELIMITER ;

CALL DemoContinue();
--------
Internally (Execution Flow)

INSERT INTO employees VALUES(1,'John');

❌ Error occurs → Duplicate Primary Key

Is handler available- YES → CONTINUE HANDLER

INSERT INTO employees VALUES (2,'Geetha');

---Row inserted successfully

SELECT * FROM employees;

Real-Time Example: OUT Parameter + Error Handling

---------------------------------------------------------------------
Used when applications need success/failure messages.


Create a stored procedure named AddEmployee to insert a new employee into the employees table and 
return the operation status.

Task
Assume an employees table exists with columns:
emp_id
name
Write a stored procedure that:
Accepts employee ID and employee name as IN parameters.
Inserts the employee record into the table.
Uses an OUT parameter to return the execution status:
'SUCCESS' → if insertion is successful
'FAILED – error occurred' → if any error happens (example: duplicate primary key).
Implement error handling using an EXIT HANDLER for SQLEXCEPTION.
Execute the procedure twice:
First call → try inserting an existing employee ID.
Second call → insert a new employee successfully.
Display the returned status message after each call.



DELIMITER $$

CREATE PROCEDURE AddEmployee(
    IN p_id INT,
    IN p_name VARCHAR(50),
    OUT p_status VARCHAR(50)
)
BEGIN
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    SET p_status = 'FAILED – error occurred';

    INSERT INTO employees1(emp_id, name)
    VALUES (p_id, p_name);

    SET p_status = 'SUCCESS';
END $$

DELIMITER ;

Calling:

SELECT @msg;

CALL AddEmployee(10, 'Asha', @msg);
SELECT @msg;

Using SIGNAL to Display Custom Error Messages
---------------------------------------------------------------------

SIGNAL allows you to raise your own error 


Create a stored procedure named CheckAge that validates a person's age before allowing further processing.

Task
Write a stored procedure that:
Accepts age as an IN parameter.
Checks whether the age is less than 18.
If age is below 18:
Raise a custom error message using SIGNAL.

Display the message:

Age must be 18 or above
If age is 18 or greater:
Return a message 'Valid age'.



DELIMITER $$

CREATE PROCEDURE CheckAge(IN p_age INT)
BEGIN
    IF p_age < 18 THEN
        SIGNAL SQLSTATE '45000'
            SET MESSAGE_TEXT = 'Age must be 18 or above';
    END IF;

    SELECT 'Valid age' AS status;
END $$

DELIMITER ;


Calling:

CALL CheckAge(10);


Produces:

ERROR 1644 (45000): Age must be 18 or above


✔ Error appears in red
✔ Perfect for validation

---------------------------------------------------------------------
✔ LOOP + LEAVE

-- procedure that continuously increments a variable and exits the loop when the value becomes greater than 5 
using LOOP and LEAVE.

syntax :LOOP_LABEL: LOOP

    statements;

    IF condition THEN
        LEAVE LOOP_LABEL;
    END IF;

END LOOP LOOP_LABEL;

example:

myloop: LOOP
    SET x = x + 1;
    IF x > 5 THEN
        LEAVE myloop;
    END IF;
END LOOP myloop;

Example :

DELIMITER $$

CREATE PROCEDURE LoopExample1()
BEGIN

    DECLARE x INT DEFAULT 0;

    myloop: LOOP
        SET x = x + 1;

        IF x > 5 THEN
            LEAVE myloop;
        END IF;

    END LOOP myloop;

    SELECT x AS Final_Value;

END $$

DELIMITER ;

CALL LoopExample1();
---------------------------------------------------------------------
✔ REPEAT Loop


syntax :REPEAT

    statements;

UNTIL condition
END REPEAT;


--  procedure that increases a counter repeatedly until its value reaches 5 using a REPEAT loop.
SET x = 1;
REPEAT
    SET x = x + 1;
UNTIL x = 5
END REPEAT;

example :

DELIMITER $$

CREATE PROCEDURE RepeatExample()
BEGIN

    DECLARE x INT DEFAULT 1;

    REPEAT
        SET x = x + 1;
    UNTIL x = 5
    END REPEAT;

    SELECT x AS Final_Value;

END $$


DELIMITER ;


CALL RepeatExample();
