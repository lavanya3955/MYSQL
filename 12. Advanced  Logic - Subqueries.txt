--------------------------------------------------------------------------------------
Subquery
--------------------------------------------------------------------------------------
A subquery (also called an inner query or nested query) is a query written inside another SQL query.
It is used when the result of one query is needed to perform another query.

First do a small task → then use that result to complete the main task
Example: Find class average & Then find students who scored above average
--------------------------------------------------------------------------------------
Types of Subqueries:
1. Single-row Subquery - Returns only one value
2. Multi-row Subquery-Returns multiple values
3. Nested Subquery-A subquery inside another subquery (multiple levels)

-----------------------------------------------------------------------------------
Single-row Subquery/ Scalar Subquery 
--------------------------------------------------------------------------------------
A scalar subquery is simply: a subquery that returns exactly ONE value (one row, one column)
Why:We use it when we need a single calculated value and want to use it inside another query.

3.Table Subquery (FROM)
-------------------------------------------------------------------------------------

A subquery used in the FROM clause that returns a table (derived table).
The inner query acts like a temporary table.

You use a subquery in FROM (table subquery) when you need to treat a calculated result 
as a table and then query it again.
You cannot directly use aggregate results (AVG, SUM, etc.) in WHERE

So we:

First calculate (inner query)
Then filter/use it (outer query)

ex:
CREATE TABLE Employees (
    emp_id INT PRIMARY KEY,
    name VARCHAR(50),
    department VARCHAR(30),
    salary INT
);

INSERT INTO Employees VALUES

Find departments where average salary is greater than 60000

GROUP BY department;

SELECT department, AVG(salary)

FROM → WHERE → GROUP BY → SELECT

WHERE runs before AVG() is calculated

When you want to reuse calculated results, First calculate once, then reuse

1.Find departments where average salary is greater than 60000

SELECT *
FROM (
    SELECT department, AVG(salary) AS avg_salary
    FROM Employees
    GROUP BY department
) AS dept_avg
WHERE avg_salary > 60000;

🔸 EXISTS

Correlated = inner query is Connected to the outer query.
Non-Correlated = inner query is Independent of the outer query.

EXISTS checks whether the subquery returns any rows or not

If subquery returns at least 1 row → TRUE
If subquery returns no rows → FALSE

EXISTS *does NOT care what you select (1, 0, columns, etc.)

NOTE:SELECT 1 is commonly used because EXISTS only checks whether rows exist—it does not care
 what values are selected.

non-corelated subquery.

Ex:Checks if subquery returns any row

"Does the Students table contain at least one student with marks > 70?"

SELECT name,marks
FROM Students 
WHERE EXISTS (
    SELECT 1 FROM Students
    WHERE marks > 70
);

SELECT name,marks
FROM Students 
WHERE EXISTS (
    SELECT name FROM Students
    WHERE marks < 40
);
---- normal query---
SELECT name, marks
FROM Students
WHERE marks > 70;

NOte:This subquery is not related to the outer query. It simply asks:

2.Finds customers who have placed at least one order.

EXISTS: Check if related records exist

Used to find records in one table that have matching records in another table.

When the subquery is correlated, meaning it refers to the current row of the outer query.

Correlated EXISTS (uses the outer table): Checked for each row, so some rows may be returned and 
others filtered out.


-- Create Customers Table
CREATE TABLE Customers (
    CustomerID INT PRIMARY KEY,
    CustomerName VARCHAR(50)
);

-- Insert Data
INSERT INTO Customers (CustomerID, CustomerName)
VALUES
(1, 'Ravi'),
(2, 'Anu'),
(3, 'Meena'),
(4, 'Kiran');

-- View Data
SELECT * FROM Customers;


-- Create Orders Table
CREATE TABLE Orders (
    OrderID INT PRIMARY KEY,
    CustomerID INT,
    FOREIGN KEY (CustomerID) REFERENCES Customers(CustomerID)
);

-- Insert Data
INSERT INTO Orders (OrderID, CustomerID)
VALUES
(101, 1),
(102, 1),
(103, 3);

-- View Data
SELECT * FROM Orders;
---------------------------------------------------
Explanation:
Think of EXISTS as asking:

"Does this customer have at least one order?"

If the answer is Yes, show the customer.

If the answer is No, don't show the customer.
------------------
here - Ravi placed 2 orders.
Meena placed 1 order.
Anu placed 0 orders.
Kiran placed 0 orders.
-----------------------
SELECT CustomerID, CustomerName
FROM Customers c
WHERE EXISTS (
    SELECT 1
    FROM Orders o
    WHERE o.CustomerID = c.CustomerID
);

SELECT CustomerID, CustomerName
FROM Customers c
WHERE EXISTS (
    SELECT customername
    FROM Orders o
    WHERE o.CustomerID = c.CustomerID
);


Here the subquery depends on the current customer (c.CustomerID), so it is evaluated for each outer row

🔸 ANY

Compare with any value

Display the names and marks of students who scored more than at least one student in the CS department.

SELECT name,marks
FROM Students
WHERE marks > ANY (
    SELECT marks FROM Students WHERE department = 'CS'
);



--------------------------------------------------------------------------------
🔸 ALL

👉 Compare with all values

Find the names and marks of students whose marks are less than every student in the CS department.

SELECT name,marks
FROM Students
WHERE marks < ALL (
    SELECT marks FROM Students WHERE department = 'CS'
);

Find the names and marks of students whose marks are greater than every student in the CS department.

SELECT name,marks
FROM Students
WHERE marks > ALL (
    SELECT marks FROM Students WHERE department = 'CS'
);
--------------------------------------------------------------------------------------

NOTE:
> ANY → Greater than at least one → Greater than MIN
< ANY → Less than at least one → Less than MAX
> ALL → Greater than every value → Greater than MAX
< ALL → Less than every value → Less than MIN
